## 1. 通用约定

- 所有哈希/地址/签名为 `0x` 前缀小写 hex。地址在 schema 中要求小写（比较前统一 `toLowerCase`）；展示时可 checksum。
- 金额：十进制字符串，固定 18 位小数（`^[0-9]+\.[0-9]{18}$`），**JSON 里禁止出现 number 类型的金额**（JCS 浮点风险）。
- 时间：RFC 3339 UTC `Z`；Mandate 里的 unix 秒也用字符串。
- ID 去标签化：`EV-xxxxxxxx`、`S-xxxxxxxx`、`SUP-xxxxxx` 均为随机 hex；文件名同理（`F01/…` 目录名只有编号）。
- 规范化：RFC 8785（JCS）；实现 `packages/core/src/canonical.ts`；测试向量 `packages/core/vectors/`。

## 2. 派生量（必须可由 CLI 独立重算）

```
file_sha256          = sha256(bytes)
manifest_bytes       = JCS(manifest.json 对象)
packet_commitment    = sha256( ascii("AFR-PKG-v1") || salt16 || manifest_bytes )
mandate_commitment   = sha256( ascii("AFR-MND-v1") || JCS(mandate.typed_data.message) )
ref_id(type-agnostic)= keccak256( ascii("AFR-REF-v1") || lineage_id16 || utf8(disclosure_set_id) )
anchor_key           = keccak256(abi.encode(submitter, uint8 type, bytes32 ref_id, uint32 version))   // 合约内
payout_key           = keccak256(abi.encode(bytes32 claim_ref_padded, uint32 decision_version))       // 合约内
manifest_sig_digest  = sha256(manifest_bytes)                        // EIP-191 personal_sign 的消息（32 字节）
statement_sig_digest = sha256(JCS(verifier_statement.statement))
decision_sig_digest  = sha256(JCS(decision 去掉 signature 字段))
scenario_sig_digest  = sha256(JCS(scenario 去掉 signature 字段))
```

注：AUTH 与 PACKET 的 ref_id 数值相同（都由 lineage+set 派生），靠合约键里的 `type` 区分命名空间；这使 CLI 只需一个派生函数。

## 4. 合约接口（Solidity 0.8.28）

### 4.1 IEvidenceAnchor

```solidity
interface IEvidenceAnchor {
    enum AnchorType { AUTH, PACKET }          // uint8 0 / 1
    struct Record { bytes32 commitment; uint64 blockNumber; }

    event Anchored(
        address indexed submitter,
        uint8   indexed anchorType,
        bytes32 indexed refId,
        uint32  version,
        bytes32 commitment,
        uint64  blockNumber
    );
    error Conflict();      // 同键不同承诺
    error BadVersion();    // version != latest + 1（且非幂等重写）

    /// 幂等：version<=latest 且 commitment 相同 → 静默返回（无事件）
    function anchor(uint8 anchorType, bytes32 refId, uint32 version, bytes32 commitment) external;

    function get(address submitter, uint8 anchorType, bytes32 refId, uint32 version)
        external view returns (bytes32 commitment, uint64 blockNumber);

    function latest(address submitter, uint8 anchorType, bytes32 refId)
        external view returns (uint32 version);
}
```

CLI 调用序列（在线）：
1. `get(submitter, AUTH, ref_id, v_auth)` → 比对 `anchors_expected[AUTH].commitment` 与重算的 `mandate_commitment`；取 `blockNumber` 作为 AUTH_ORDER 的 `anchor_block`（不依赖回执）。
2. `get(submitter, PACKET, ref_id, v_pkt)` → 比对重算 `packet_commitment`；`blockNumber` 用于 D。
3. `latest(submitter, PACKET, ref_id)` > `v_pkt` → `superseded.packet = true`；`latest(submitter, AUTH, ref_id)` > `v_auth` → `superseded.auth = true`（advisory）。
4. `eth_getTransactionReceipt(payment_tx)` → `RECEIPT_PAYMENT`；`payment_block` 用于 AUTH_ORDER：`anchor_block + G <= payment_block`。
5. `eth_blockNumber` → D 检查。
6. anchors.json 存在时 `eth_getTransactionReceipt(anchors.packet.tx_hash)`，与 `get` 的 blockNumber 比对，不一致仅 warning。

### 4.2 IClaimVault

```solidity
interface IClaimVault {
    event Payout(bytes32 indexed key, bytes32 indexed claimRef, uint32 decisionVersion, address to, uint256 amount);
    error AlreadyExecuted();
    error NotOperator();

    function token() external view returns (address);       // AFR-TEST-USD
    function operator() external view returns (address);
    function executed(bytes32 key) external view returns (bool);

    /// key = keccak256(abi.encode(claimRef, decisionVersion)); 先置 executed 再 transfer（CEI）
    function payout(bytes32 claimRef, uint32 decisionVersion, address to, uint256 amount) external;
}
```

`claimRef` = `bytes32(uint256(uint128(claim_ref)))`（16 字节左填零）。链上只暴露随机 claimRef、金额、收款地址、决定版本。

## 5. 规则引擎输出（rule_facts）

规则引擎输出对象（进入 `verifier_statement.statement.rule_facts_digest`，evalkit 用于"硬字段未改写"断言）：

```json
{
  "amount_within_cap": true,
  "payee_in_registry": true,
  "within_validity_window": true,
  "duplicate_settlements": 0,
  "tool_authorized": true,
  "mandate_effective_version": 1,
  "auth_order_satisfied": true,
  "settled_amount": "8.000000000000000000",
  "eligible_loss": "8.000000000000000000",
  "contract_rule_clauses": { "VC-01": "pass", "VC-02": "pass", "VC-03": "pass", "VC-04": "pass", "VC-05": "pass" }
}
```

AI 输入包含此对象（只读）；AI 输出 schema 中**没有**这些字段，因此"改写"在结构上不可能，evalkit 额外检查 AI 的 `statement` 文本中不出现与 rule_facts 相反的断言（关键词表：见 04 文档）。
