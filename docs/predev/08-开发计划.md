# 08 · 开发计划（分阶段 · 带 DoD）

> 状态：PLAN。这是阶段级路线图，不是逐任务实施计划。逐任务（TDD、每步 2–5 分钟）的实施计划在 Gate 0 通过后按 `writing-plans` 规范生成到 `docs/superpowers/plans/`，一个子系统一份。
> 原则：作者与校验分车道（写的人不给自己盖章）；每阶段有可机检的 DoD；任何阶段不得让 PRD 的"NOT VERIFIED"状态提前变绿。

## 阶段总览

```
G0 ─ Spikes（S2→S1→S3→S4）─┐
                            ├─▶ P1 core + vectors ─▶ P2 contracts ─▶ P3 verifier-cli ─┐
                            │                                                           ├─▶ P6 web ─▶ P7 demo pack ─▶ P8 submission
                            └─▶ P4 gateway + verifier-svc + agent ─▶ P5 fixtures + evalkit ┘
```

P1–P3 与 P4–P5 可并行（两条车道），P6 依赖两条都完成。

## G0 · 解封 Spike（见 02 文档）

**DoD：** `spikes/RESULTS.md` 四行 PASS；触发的回退已写回 PRD/ADR；`docs/predev/00-README.md` Gate 0 全勾。
**校验：** 独立子代理只读复核 RESULTS 证据目录是否与判据一一对应。

## P1 · `packages/core` + 黄金向量

范围：JCS、sha256/keccak、`packetCommitment`、`mandateCommitment`、`refId`、EIP-191 签名/恢复、EIP-712 typed-data 构造与恢复、ajv 校验器（加载 `schemas/*.v1.json`）、`redact()`。
**DoD：**
- `pnpm --filter @afr/core test` 全绿；覆盖率 ≥ 90%（core 是信任根，例外要写理由）。
- `packages/core/vectors/*.json` ≥ 10 条，含 RFC 8785 附录向量；`pnpm vectors` 在 Node 22 与浏览器（vitest browser mode）结果一致。
- 无 `number` 类型金额通过 schema（有反向测试）。
**校验：** 第二人/子代理用独立脚本（不 import core）重算 3 条向量。

## P2 · `contracts/`

范围：`EvidenceAnchor`、`ClaimVault`、`AFRTestUSD`、`Deploy.s.sol`（写地址到 `trusted_signers.json` 的 TS 后处理）。
**DoD：**
- `forge test`：幂等/冲突/版本跳跃/多提交者隔离/CEI/AlreadyExecuted/非 operator 拒绝 全部通过；fuzz 512 runs。
- `forge script Deploy` 在 anvil(chain 1439) 通过；对 anvil(chain 1776) **revert**（有测试）。
- 测试网部署一次，地址进 `trusted_signers.json`，Blockscout 链接进 README（仅展示）。
**校验：** 子代理读合约源码对照 ADR-007/008 逐条打勾；`slither` 无 high。

## P3 · `packages/verifier-cli`

范围：`afr-verify <zip> [--offline|--rpc|--trust|--json|--expect-set]`；13 个检查项；包级 superseded/warnings/overall/caps；负例生成器；安全负例。
**DoD：**
- `pnpm negatives`：原包 + N01–N11 + X01–X05 与 `expected.json` 100% 一致。
- 人可读输出含 §4.3 两条固定标签原文（快照测试）。
- 从任意 cwd 运行读到的是安装目录 `trust/trusted_signers.json`（有测试：cwd 放一个假 trust 文件，断言被忽略且有 warning）。
- `--offline` 下链上项全部 Unknown 且逐项列出。
- 零依赖平台：`grep -r "apps/" packages/verifier-cli/src` 为空；package.json 无对 apps/* 依赖。
**校验：** 子代理在干净容器（无 .env、无网络）跑 `--offline`；再带 `--rpc` 归档端点跑在线。

## P4 · `apps/gateway` + `apps/verifier-svc` + `packages/agent` + `packages/chain` + `apps/fixture-server`

范围：Mandate 接收与 AUTH 存证（G/D）；Payment 状态机（含 Aborted）；约束检查（金额/收款人登记表/有效期/工具）；Agent 三工具循环；支付广播（legacy、显式 gas）；证据事件签名；Claim 状态机（含 Not Eligible / Rejected for Processing / flags）；eligible_loss；包两阶段构造与导出；verifier-svc 独立进程签 statement；ClaimVault payout；Agent 钱包出账监听。
**DoD：**
- 状态机测试：§15 每个状态至少一条进入/退出测试；非法迁移拒绝。
- 端到端（anvil + 本地 fixture-server + mock 模型）：§16 步骤 1–13 自动跑通，产出的 ZIP 用 P3 CLI 验证 `overall = all_pass_in_scope`。
- 授权存证超时 → Payment Aborted，无广播（用 anvil 停矿模拟）。
- verifier-svc 与 gateway 不共享 `.env`；进程内无对方私钥（测试：环境变量断言）。
- 主网防线：`packages/chain` 在 chainId≠1439 抛错（测试）。
**校验：** 子代理跑 e2e 并用 CLI 验证；再故意改一个 evidence 文件确认 CLI Fail。

## P5 · `fixtures/` + `packages/evalkit`

范围：F01–F06（scenario、mandate、evidence、rule_facts、policy、ground_truth）；ID 去标签化工具；扰动生成；评测器 S1–S12；提示模板 n-gram 重叠检查；`eval:live`。
**DoD：**
- `pnpm eval` 产出 `REPORT.md`，6×4×3 = 72 次运行全部记录（含失败原文）。
- **正向门槛**（Story 4.3）全过，否则 REPORT 顶部 "AI capability: NOT PASSED" 且 web 徽章读取此状态——不允许手改徽章。
- 提示模板与夹具 n-gram 重叠检查通过。
- `sha256(ground_truth.json) ∉ input_digests`（S9）对全部运行为真。
**校验：** 子代理替换一个夹具的注入文本为全新措辞（不在 P-paraphrase 集合内）重跑，类别仍正确；再把一个 PI 夹具的注入内容删掉，断言评测变为 Needs Information 而非仍判 PI（防"看标题猜答案"）。

## P6 · `apps/web`

范围：操作者视图（签 Mandate、看时间线）、审核员视图（验证结果、AI 报告、决定表单）、评委视图（能力徽章 Implemented/Not Implemented/Planned、四态结果、一键导出、Spike/评测记录链接）。
**DoD：**
- Playwright 跑 §16 步骤 1–13（真实 MetaMask 用 synpress 或注入测试钱包）。
- 每页有 §20 步骤 9 要求的标注条（测试资产/合成攻击/外部模型/软件级声明/人工步骤）。
- 验证页文案不超出 §4.3 上限（快照测试锁定固定句）。
**校验：** 子代理按评委视角走一遍并对照 Story 6.1 五条打勾。

## P7 · 演示包

范围：`seed-session` 脚本；预置支付（满足全部规则）；拒赔夹具 F03 的签名固定包；负例 ZIP 与生成脚本；3 分钟视频（按 S4 修订的 §24）；现场 checklist。
**DoD：**
- 两个独立会话各跑一遍完整路径，产出两个不同 lineage 的最终包，CLI 均 `all_pass_in_scope`。
- 视频：连续录制；若有可见时间压缩，屏显标注存在且 `docs/demo/VIDEO-LOG.md` 记录每处压缩时长。
- 现场降级预案表（模型不可用 / RPC 不可用 / 钱包不可用）每条有演练记录。
**校验：** 子代理看视频脚本与 VIDEO-LOG 是否一致；随机抽一个负例现场重生成并验证。

## P8 · 提交

**DoD：** §28 清单逐项有文件路径；`trusted_signers.json` 的 `repo.commit` = 提交 commit；CLI npm 发布带 provenance；README 顶部状态从 "NOT STARTED" 改为 "P0 IMPLEMENTED（见验证记录）"——**仅当** P1–P7 DoD 全部有证据。
