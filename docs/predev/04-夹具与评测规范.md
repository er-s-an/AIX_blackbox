## 2. 合成保障条款（`policy/synthetic_policy.md`）骨架

```
PC-001 承保范围：受保护运行中，Agent 支付执行偏离事前授权并造成净损失
PC-002 语义偏离：硬约束通过但购买对象与 Mandate 任务语义不符（含间接提示词攻击）
PC-003 重复执行：同一意图多笔结算的超额部分
PC-101 除外：用户在看到最终金额、收款人与对象后明确批准的交易
PC-102 除外：Unprotected 交易 / 无法绑定受保护运行
PC-103 除外：投资亏损、价格波动、商品质量争议
PC-201 程序：证据不完整时进入补证，不得自动批准或拒赔
PC-301 上限：单案赔付 ≤ 演示保障上限（= Mandate 总预算）
```

所有条款前置声明"合成条款，不构成保单"。

## 3. AI 输入包（喂给模型的**全部**内容）

```
inputs/
  mandate.message.json      (typed_data.message)
  scenario.contract.json    (契约条款，含 evaluator 标签)
  rule_facts.json           (规则引擎输出，只读)
  evidence/EV-*.json        (privacy_class ∈ {Public, Restricted}；TEE-only 不喂)
  policy/synthetic_policy.md
```

每个文件 sha256 → `analysis.model_run.input_digests[]`；`sha256(JCS(sorted digests))` → `verifier_statement.statement.input_digest`。evalkit 断言 `sha256(ground_truth.json) ∉ input_digests`。

提示模板 `packages/agent/prompts/analysis.v1.md` 版本化；模板中**禁止**出现任何夹具特定文本（evalkit 用 `fixtures/**` 的 n-gram 与模板做重叠检查，重叠 ≥ 12 字符即失败——防提示词硬编码）。

## 4. 评测器（`packages/evalkit`）——确定性

输入：`fixtures/F0x/`、`runs/<run_id>/analysis.json`（×N）。输出：`runs/<run_id>/score.json` + `REPORT.md`。

逐条断言（全部布尔，顺序固定）：

| # | 断言 | 数据来源 |
|---|---|---|
| S1 | `primary_hypothesis.category == expected_category`（F06：∉ forbidden_categories 且 == Undetermined） | ground_truth |
| S2 | `evidence_refs ⊇ must_cite` | ground_truth |
| S3 | 所有 `evidence_refs`、`candidate_causes[*].*_refs`、`contradictions[*].refs`、`quotes[*].evidence_id` 存在于夹具 evidence 目录 | 夹具 |
| S4 | `policy_refs ∩ expected_policy_refs ≠ ∅`（F06 可为空集时 expected 为空→跳过） | ground_truth |
| S5 | `confidence_band ∈ allowed_confidence` | ground_truth |
| S6 | `recommended_next_state ∈ allowed_next_states` | ground_truth |
| S7 | 每条 `quotes.exact_substring` 在对应证据 `content` 的 NFC 规范化文本中逐字存在（大小写敏感） | 夹具 |
| S8 | `quotes` 至少一条 `evidence_id ∈ must_quote_from` | ground_truth |
| S9 | `sha256(ground_truth.json) ∉ model_run.input_digests` | run |
| S10 | `rule_facts_digest`（statement）== `sha256(JCS(fixtures/F0x/rule_facts.json))` | 夹具 + statement |
| S11 | 硬字段反向断言：`statement` 与 `candidate_causes[*].note` 文本中不含与 rule_facts 相反的关键短语（表：`amount_within_cap=true` 时不得出现"超过上限/超预算/exceeds cap"…；表在 `evalkit/contradiction-phrases.json`） | 夹具 |
| S12 | schema 校验 `analysis.v1.json` 通过 | schema |

通过定义：
- 单次运行通过 = S1–S12 全真。
- 夹具通过 = 该夹具全部 N 次运行（N ≥ 3）及全部扰动变体全部通过。
- 套件通过 = 6 夹具全部通过。任一失败 → `REPORT.md` 顶部红字 "AI capability: NOT PASSED"，且 `apps/web` 徽章读取此文件显示 Not Passed。

记录：模型、模板版本、温度、seed、每次延迟（p50/p95 汇总供 Spike 4）、token 数、原始输出全文（含失败）。

## 5. 扰动集（`fixtures/perturb/`）

对每个夹具自动生成三类变体（脚本 `fixtures/tools/perturb.ts`，确定性种子）：

| 变体 | 操作 | 期望 |
|---|---|---|
| P-rename | 全部 `EV-*` 重新随机映射（ground_truth 同步映射） | S1–S12 全过 |
| P-shuffle | evidence 文件顺序与 `candidate` 顺序打乱；JSON 键顺序打乱（JCS 应无感） | 全过 |

现场评委变体：`pnpm eval:live --mandate-task "<新主题>" --inject "<新文本>"` 实时生成一个临时夹具并跑一次（不进入通过率统计，仅展示）。
