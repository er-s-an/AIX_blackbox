# 01 · 技术决策记录（ADR）

> 状态：ACCEPTED（进入 Spike 前的基线；Spike 结果可推翻标注 *可被 Spike 推翻* 的条目）
> 依据：PRD v1.3 §4、§20。所有条目均为目标决策，无任何已实现代码。
> 日期：2026-09-05

每条格式：**决策** → 理由 → 放弃项 → 推翻条件。

## ADR-001 · 单仓库 monorepo（pnpm workspaces）

**决策：** 一个 git 仓库，pnpm workspaces 管理 `apps/*`、`packages/*`、`contracts/`。

- 理由：黑客松节奏下跨包改动频繁（schema 改一处，Gateway/CLI/前端同时受影响）；单仓库让 schema 与测试向量成为唯一真源；评委 clone 一次即可复现全部。
- 放弃：多仓库（CLI 独立仓库）——PRD 要求 CLI "随其开源仓库发布信任配置"，但"开源仓库"可以是 monorepo 中的 `packages/verifier-cli`，发布时通过 npm 包 + git tag 满足"版本化发布"。
- 推翻条件：无。

## ADR-002 · 语言与运行时：TypeScript（Node 22 LTS）全栈；合约 Solidity 0.8.28 + Foundry

**决策：** Gateway、验证者服务、CLI、前端、评测器全部 TypeScript；合约用 Foundry。

- 理由：PRD §20 技术基线已定 viem + Foundry；单语言减少 JCS/哈希实现分歧（同一个 `packages/core` 被 Gateway 与 CLI 共用，测试向量只需验一次）。
- 放弃：Python 评测器——会引入第二套 JSON 规范化实现，增加跨语言一致性风险。
- 推翻条件：无。

## ADR-003 · JSON 规范化：RFC 8785（JCS），库选 `canonicalize`（npm）

**决策：** 使用 npm `canonicalize`（Anders Rundgren 参考实现的 JS 移植）做 JCS；`packages/core` 封装为 `canonicalJson(obj): Uint8Array`，并附 RFC 8785 附录测试向量 + 本项目测试向量。

- 理由：JCS 是 PRD 指定标准；`canonicalize` 是最贴近参考实现的库，体积小、无依赖。
- 放弃：`json-stable-stringify`（不是 JCS，数字序列化不符合 ES6 规则）；自己写（浮点序列化规则易错）。
- 约束：所有承诺输入对象**禁止浮点数**（金额用十进制字符串，如 `"8.000000000000000000"`），schema 层强制 `type: string, pattern`。这一条消除 JCS 中最容易踩坑的部分。
- 推翻条件：测试向量在 Node 22 / Bun / 浏览器三环境不一致 → 改用自实现并冻结。

## ADR-004 · 哈希与承诺：SHA-256（`@noble/hashes`），域分离定长前缀

**决策：**
- 文件摘要：`sha256(file_bytes)`，hex 小写。
- 包承诺：`sha256(domain || salt || canonicalManifestBytes)`，`domain = ASCII "AFR-PKG-v1"`（10 字节定长），`salt = 16 字节 CSPRNG`（定长），因此段边界无歧义。
- Mandate 承诺：`sha256("AFR-MND-v1" || canonicalMandateBytes)`（Mandate 不加盐：它已含用户签名，且授权存证要求可由 Gateway 与 CLI 独立重算）。
- ref_id：`keccak256("AFR-REF-v1" || lineage_id(16B) || utf8(disclosure_set_id))`，写入合约的 bytes32。
- 理由：`@noble/hashes` 纯 JS、经审计、浏览器/Node 同构；keccak 只用于链上键以贴合 EVM 习惯，链下内容承诺统一 SHA-256 与 PRD 一致。
- 放弃：Node `crypto`（浏览器不可用，CLI 未来若做 WASM 版会分叉）；Blake3（PRD 已定 SHA-256）。
- 推翻条件：无。

## ADR-005 · 签名体系：三类密钥，全部 secp256k1 + EIP-191/EIP-712，不引入 Ed25519

**决策：**

| 角色 | 密钥 | 签什么 | 方式 |
|---|---|---|---|
| 用户 | MetaMask 账户 | AFR Mandate | EIP-712 typed data（domain.chainId = 1439） |
| Gateway | 服务器热钱包 A | Evidence Manifest、Evidence 事件 | EIP-191 personal_sign over `sha256(canonical bytes)`（签 32 字节摘要） |
| 验证者 | 服务器热钱包 B（与 A 物理分离进程） | 执行环境声明（verifier_statement） | 同上 |
| 提交者 | 热钱包 A（或独立 C） | EvidenceAnchor / ClaimVault 交易 | 普通交易签名 |

- 理由：一套曲线、一套恢复函数（viem `recoverAddress` / `recoverTypedDataAddress`），CLI 依赖最少；trusted_signers.json 只需存地址 + key_id + 角色 + 有效期，不存公钥原文（地址即公钥承诺）。
- 放弃：Ed25519 用于服务端签名（更快，但要额外引入 `@noble/ed25519` 并让 CLI 支持两套验证；黑客松不值得）。
- 推翻条件：无。

## ADR-006 · Mandate EIP-712 类型定义（冻结 v1）

```
domain = { name: "AgentFlightRecorder", version: "1", chainId: 1439, verifyingContract: <EvidenceAnchor 地址> }

AFRMandate {
  string   mandate_id;          // uuid v4
  string   task;                // 自然语言任务
  string   currency;            // "AFR-TEST-USD"
  string   total_budget;        // 十进制字符串
  string   per_tx_cap;          // 十进制字符串
  bytes32  supplier_registry;   // 签名供应商登记表的 sha256
  uint64   valid_from;          // unix 秒
  uint64   valid_until;
  string   confirmation_mode;   // "none" | "human_second_confirm"
  bytes32  policy_hash;         // 合成条款文件 sha256
  address  agent_wallet;        // 演示热钱包地址
}
```

- 理由：全部字段为确定性标量；金额为字符串避免 uint 精度歧义与 JCS 浮点问题；`verifyingContract` 指向 EvidenceAnchor 使签名与部署绑定（换合约必须重签）。
- 放弃：把供应商列表内联（typed data 数组显示体验差；改为登记表哈希）。
- 推翻条件：Spike 1 中 MetaMask 对 `uint64` 或 `bytes32` 的显示不可接受 → 改为 `string`，保持字段名不变。*可被 Spike 推翻*

## ADR-007 · EvidenceAnchor 合约键与存储

**决策：**

```solidity
enum AnchorType { AUTH, PACKET }
struct Record { bytes32 commitment; uint64 blockNumber; }
// key = keccak256(abi.encode(submitter, anchorType, refId, version))
mapping(bytes32 => Record) public records;
mapping(bytes32 => uint32) public latestVersion;  // keccak256(abi.encode(submitter, anchorType, refId)) -> version
event Anchored(address indexed submitter, uint8 indexed anchorType, bytes32 indexed refId, uint32 version, bytes32 commitment, uint64 blockNumber);

function anchor(uint8 anchorType, bytes32 refId, uint32 version, bytes32 commitment) external;
// 规则：version == latestVersion + 1 → 写入；version <= latest 且 commitment 相同 → 幂等 no-op（不 revert，不发事件）；commitment 不同 → revert Conflict
function get(address submitter, uint8 anchorType, bytes32 refId, uint32 version) external view returns (bytes32 commitment, uint64 blockNumber);
function latest(address submitter, uint8 anchorType, bytes32 refId) external view returns (uint32);
```

- 理由：CLI 全部通过 `get` / `latest` 两次 eth_call 完成承诺比对 + Superseded 检测，不依赖历史回执/日志；submitter 进入键使任何人都能写但互不干扰，无需 owner。
- 放弃：owner-only 写入（增加密钥管理，且"任何人都可锚定自己的承诺"更符合公共登记语义）；用事件作为唯一记录（公共 RPC 截断历史，eth_getLogs 不可靠）。
- 推翻条件：Spike 2 发现 eth_call 对 struct 返回有 ABI 兼容问题 → 拆为两个 mapping。*可被 Spike 推翻*

## ADR-008 · ClaimVault 合约

**决策：**

```solidity
// 幂等键 = keccak256(abi.encode(claimRef, decisionVersion))
mapping(bytes32 => bool) public executed;
address public immutable token;     // AFR-TEST-USD
address public operator;            // 演示审核员执行地址（可轮换）
event Payout(bytes32 indexed key, bytes32 indexed claimRef, uint32 decisionVersion, address to, uint256 amount);
function payout(bytes32 claimRef, uint32 decisionVersion, address to, uint256 amount) external onlyOperator;
// executed[key] == true → revert AlreadyExecuted；成功 → executed=true 后 transfer
```

- 理由：合约级幂等（PRD §5.6）；claimRef 为 16 字节随机值左填充为 bytes32，链上不暴露 Claim 编号。
- 放弃：多签 operator（P1）；pull 模式（用户自领，演示体验差）。
- 推翻条件：无。

## ADR-009 · 演示代币：自部署 ERC-20 `AFR-TEST-USD`（OpenZeppelin ERC20，18 位小数，无 permit）

- 理由：PRD §20 决策；不借用任何真实稳定币品牌；自部署可无限 mint 用于每会话独立预置。
- 放弃：官方测试网 USDT/USDC（品牌风险 + 领取受限）；原生 INJ 计价（gas 与计价混用，金额显示混乱）。

## ADR-010 · 证据包容器：ZIP（`fflate`），确定性写入

**决策：** 用 `fflate` 生成 ZIP；条目按路径字节序排序；所有条目 mtime 固定为 `1980-01-01T00:00:00Z`（ZIP 最小值）；压缩级别固定 6；不写 extra fields。

- 理由：`fflate` 纯 JS、同构、无依赖；确定性写入使"同一 Manifest 两次导出字节相同"，便于回归测试（PRD 说容器属性不作身份，但确定性能省很多解释）。
- CLI 读取侧：拒绝 `..`、绝对路径、重复条目、条目数 > 500、单文件 > 50 MB、总解压 > 200 MB；只解到内存不落盘；不跟随符号链接。
- 放弃：tar（浏览器侧支持差）；JSON 单文件（评委直觉是"证据包 = zip"）。

## ADR-011 · 文件清单排除集合与目录布局（冻结）

```
manifest.json               ← 排除（自身）
proofs/manifest.sig.json    ← 排除（签名不能签自己）
anchors.json                ← 排除（事后提示）
proofs/salt                 ← 列入（16 字节十六进制文本）
proofs/verifier_statement.json ← 列入
mandate.json, analysis.json, decision.json, README.md, evidence/**, scenario.json ← 列入
```

- 理由：PRD §4.4 三项固定；盐必须列入，否则可被替换后重算承诺。

## ADR-012 · Web 框架：Next.js 15（App Router）前端 + Fastify 后端；SQLite（better-sqlite3）状态库

- 理由：单机自托管、零外部服务；SQLite 单文件即"案件库"，便于演示复现与打包；Fastify 轻、TypeScript 友好。
- 放弃：Postgres（部署负担）；tRPC（评委读 REST 更直观，且 CLI 不应依赖任何平台 API）。
- 推翻条件：无。

## ADR-013 · Agent 运行时：最小自研循环（无 LangChain/LangGraph）

**决策：** `packages/agent` 用 Vercel AI SDK `generateText` + 手写工具循环（3 个工具：`search_suppliers`、`fetch_page`、`request_payment`）；外部页面来自本地 fixture 服务器（合成攻击页面）。

- 理由：PRD 只需 2–3 次模型调用的受控购买路径；框架会带来不可控的 prompt 与工具调用序列，影响 Spike 4 计时与证据可复现。
- 模型：默认 OpenAI-compatible 接口（便于在 Spike 4 后按延迟换供应商）；分析步骤与购买步骤可用不同模型。分析步骤要求 JSON schema 输出（structured output）。
- 放弃：LangGraph、AutoGen。

## ADR-014 · AI 评测器：确定性程序，`packages/evalkit`

- 输入：夹具目录 + 模型输出 JSON；输出：逐项评分 JSON + Markdown 报告。
- 不调用任何 LLM；"理由"字段只回显不评分。
- 运行矩阵：6 夹具 × 4 变体（原 + 3 扰动）× 3 次 = 72 次调用，记录 p50/p95 延迟作为 Spike 4 副产品。

## ADR-015 · 信任配置分发：`packages/verifier-cli/trust/trusted_signers.json` 随 npm 包与 git tag 发布

- CLI 从 `import.meta.dirname` 相对路径读取（安装目录），不读 cwd；`--trust <path>` 覆盖；发现包内同名文件仅警告。
- 每次部署合约或轮换密钥 → 改此文件 → 提交 → 打 tag → 发布 npm。`README` 写明"信任配置的真实性 = 该仓库发布的真实性"。

## ADR-016 · RPC 策略

- 平台侧：公共端点 `https://k8s.testnet.json-rpc.injective.network/`，失败回退归档端点。
- CLI 默认：归档端点 `https://testnet.evm.archival.chain.virtual.json-rpc.injective.network/`（在信任配置内），`--rpc` 覆盖。
- 全部读取用 eth_call / eth_getTransactionReceipt / eth_blockNumber；**不用** eth_getLogs 作为验证依据；不使用 finalized/safe tag。
- 交易：legacy type-0，`gasPrice` 与 `gas` 显式；Spike 2 记录实际用值。*可被 Spike 推翻（type-2）*

## ADR-017 · 密钥与配置管理（演示级）

- 三把服务端私钥来自 `.env`（`GATEWAY_PK`、`VERIFIER_PK`、`OPERATOR_PK`），`.env` 进 `.gitignore`；仓库提供 `.env.example`。
- 验证者服务与 Gateway 为两个进程、两个 `.env` 文件、两个系统用户（或两个容器），是"独立验证者"在 P0 的物理含义。
- 私钥不出现在任何日志、包或 API 响应；`packages/core` 提供 `redact()` 用于日志。

## ADR-018 · 测试策略

- 单元：Vitest（`packages/*`）；合约：Foundry `forge test`（含幂等/冲突/版本跳跃的 fuzz）。
- 黄金测试向量：`packages/core/vectors/*.json`（JCS、包承诺、Mandate 摘要、ref_id），CLI 与 Gateway 各自跑同一组。
- 负例：`packages/verifier-cli/negatives/generate.ts` 产 N01–N11，测试断言每个负例的四态/标记结果。
- 端到端：`apps/e2e` 用 Playwright 跑 §16 路径（对本地 anvil fork 与真实测试网各一套配置）。

## ADR-019 · 明确不做（P0）

- 不做账号系统（单租户演示，角色靠 URL 前缀 + 演示口令）。
- 不做 Merkle / 逐版本存证 / TEE / precompile。
- 不做 x402 / AP2 / VI 适配器；只提供 `docs/predev/06-字段映射表.md`。
- 不做主网任何部署脚本入口（`--network mainnet` 直接 exit 1）。
