# 实施修订与验收边界

日期：2026-09-05。依据本轮审查和用户明确授权：推进实现并进行真实测试网、真实模型实测；模型不可用时继续其余实现，保留 AI 未验证状态。

本文优先于 v1.3、ADR 和旧 Spike 表中的冲突文字。不是通过记录。

1. AUTH 承诺绑定完整 `mandate.json`（format_version、typed_data、signature、signer），包括签名域；禁止只哈希 message。付款前存证因此绑定已签署对象。增加事后补签负例。
2. lineage_id 在授权准备时生成，随后 Payment、Claim 继承。同一谱系的 AUTH 以 full 命名空间引用，public 包引用同一 AUTH；PACKET 按披露集派生。
3. 链上版本为单独递增的 anchor sequence；packet_version 为内容版本。manifest 中同时签署 packet_version 和 PACKET anchor.version，首个最终包无论内容版本多少均使用存证序号 1。后续最终包使用最新序号+1。Superseded 比较 anchor sequence。P0 不上链中间包。
4. Mandate 新增签署字段 mandate_version、allowed_tools、asset_address、lineage_id；用户二次确认绑定最终收款人、资产、金额、资源、mandate_id。
5. Evidence 事件明确 schema、内容摘要和签名摘要，支付/赔付的 tx hash 来自签名 evidence。CLI 不执行包内 URL。删除 anchors.json 仅丢失包锚交易提示，不影响支付/赔付检查；警告，不制造 Unknown。包外信任不从包内导入。
6. Ground truth 隔离采用显式模型请求 allowlist、实际 messages/tools 请求摘要记录；推理模块不读取 ground_truth。摘要排除仅为额外检查，不是无泄漏证明。真实输出和失败全部保留。模型元数据由调用边界填写，不由模型自报。
7. Paid、Denied、Not Eligible、Rejected for Processing、Payout Failed 都可归档。未发生支付或赔付按明确结果 profile 返回 Not Present；已失败的交易如实 Fail，不将失败包全部通过。无攻击对照的下一步为 No Claim（不进入赔付审核）。
8. 决定签署 payout_to、asset_address、payout_amount；支付后决定冻结。合约按 claim_ref 限制一次成功赔付，失败可使用同一决定重试；跨版本不能重复赔付。P0 不做追加赔付。
9. 本轮允许技术准备、实现与 Spike 交错推进，取代旧 Gate 0 的全局停工条件。T+72h、MetaMask 弹窗、真实 AI 评测、公开发布分别记录，未完成不得标 PASS。自动化测试钱包真实 EIP-712 签名不等于 MetaMask UI 已验证。
10. 使用已有测试钱包作为部署资金来源，AFR 服务端密钥独立生成并按进程保存。默认绑定 loopback；远程部署必须启用 TLS。SQLite 中案件载荷应用层 AES-256-GCM 加密，角色权限与访问审计必须实现。
11. 许可证采用先前建议的 MIT；本轮不自动创建 GitHub 仓库、发邮件或发布 npm。CLI 本地可安装，发布来源使用实际版本信息，不能伪造 repo URL/commit。
12. 真实集成验收不使用 mock AI、mock RPC 或编造 tx。合成任务与攻击页面是公开声明的测试输入，Agent 购买、AI 分析和测试网执行必须真实；确定性单元与负例测试可用本地 Anvil，但不作为测试网证据。
